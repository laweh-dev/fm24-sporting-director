# 📁 Repository Structure

This document explains how the whole project fits together — the layout, what each piece does, and how the two user paths (Colab and local) share the same core.

---

## The guiding principle

**One engine, two front doors.** All the real logic lives in `src/fm_copilot/`. The Colab notebook and the local launchers are both thin wrappers that call the same code. Fix a bug once, both paths benefit.

---

## The key file: `pipeline.py`

This is what makes "one engine, two front doors" work. It exposes a single function:

```python
def run_report(config: dict) -> str:
    """
    The complete pipeline. Both Colab and local launchers call this.
    Returns the path to the generated report.html.
    """
```

- **Local launcher** loads `config.yaml`, calls `run_report(config)`, opens the result
- **Colab notebook** builds the same config dict from uploaded files + a pasted key, calls `run_report(config)`, displays the result inline

Same function. Same output. Two doors.

---

## How the two user paths compare

| | **Colab (notebook)** | **Local (launchers)** |
|---|---|---|
| Install anything? | ❌ Nothing — runs in browser | ✅ Python once |
| Best for | Everyone, especially non-technical | Power users, offline use |
| Where data goes | Uploaded to Google's Colab session | Stays 100% on your machine |
| Speed | Slightly slower (shared free compute) | Fast |
| How to start | Click "Open in Colab" in README | Download ZIP, double-click setup |
| API key | Pasted into a secure Colab input | Saved in local config.yaml |

Both call the same engine, so reports are identical.

## What goes in `.gitignore`

Critical — protects users from accidentally publishing private things:

```
config/config.yaml          # their API key
data_uploads/*.html         # their save data
data_uploads/*.xml
output/*.html               # their generated reports
context/squad-identity.md   # their squad specifics (optional)
context/transfer-history.md
wizard_answers.json         # pre-filled wizard answers
__pycache__/
venv/
.DS_Store
```

The `.example` and template versions are committed; the real user-filled versions never are.
